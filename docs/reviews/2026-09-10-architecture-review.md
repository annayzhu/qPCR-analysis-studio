# qPCR Analysis Studio：由外到内的架构审查与重构

日期：2026-09-10。基线：`6444d54`。工作分支：`refactor/session-and-presentation`。

## 结论

问题不在于 TypeScript，也不是所有空值判断都多余。真正的复杂度来自职责混合：状态修改顺带计算整套结果、同一个图表复制两份、导出准备参与普通渲染，以及导入边界已经规范化的数据仍被声明成大量可选字段。

本次选择减少执行路径和重复规则，而不是把工作台替换成另一套通用框架。没有改动 qPCR 公式、同板内参配对、人工排除原则或用户提供 Δ 值的权威性；没有引入服务器计算、数据库、事件总线或插件系统。

审查不是“已经证明全系统最优”。下面分别标明已经修正与仍存在的债务。

## 逐层发现与处理

| 层次 | 原设计问题及证据 | 本次处理 |
| --- | --- | --- |
| 交互/显示 | `ResultExplorer` 和 `SuppliedResultExplorer` 各有一套 SVG；一套保留长名，另一套直接截断；原始路径还静默截取前 40 个样本 | 统一 `ExpressionChart`，移除静默截断；两路径共享长名换行、误差线、SVG/PNG；保留各自的计算与方法说明 |
| 导入纠错 UI | 半宽导入卡片中的问题行要求至少 585px，操作按钮被水平裁切 | 修改原规则为“定位＋解释、下一行操作”，不再叠加媒体查询补丁 |
| 板工作区 | 每个网格单元 `.find()` 当前板，每次再 `.includes()` 所选孔 | 建立当前板位置索引和选择集合，单元查找改为 O(1) |
| 状态命令 | 成功和失败均构造完整 read model，React 丢弃后再投影；`apply` 还为验证额外做一次完整计算 | 命令只返回 state/error；应用前只验证对齐；视图按依赖计算 |
| 计算视图 | 草稿变化使已应用结果、已应用 QC 重新计算；draft=applied 时 QC 仍算两次 | 单工作台、单前态投影复用；没有全局缓存或第二份结果权威状态 |
| 不必要接口 | 通用 `previewAnalysisSessionChange` 除布局转移外只返回 `none` | 删除该包装，直接调用已有布局预览函数 |
| 批量编辑 | 改 K 个孔对 N 个孔做 K 次 map；恢复/转移重复走相同路径 | `assignWellAnnotations` 按指令顺序一次索引、惰性复制数组；保持重叠移动、重复赋值的逐步审计含义 |
| 基础统计 | Mean、样本 SD、SEM、指数传播在 QC/计算/导出中复制 | 合并为一个小的纯函数模块 `statistics.ts`；不合并不同科学策略 |
| 复孔 QC | 已过滤排除孔后再次检查；为了检查编号连续性，创建长度等于最大编号的数组 | 去掉重复筛选；直接验证排序编号等于 index+1，避免异常编号造成大规模内存分配 |
| 导入模型 | 每行其实已构造全部字段，`PartialWell` 却允许大量 undefined，导致后续重复兜底 | 改为字段必备的 `ParsedWell`；空字符串/null 明确表示缺失，保留入口数值校验 |
| 对齐检查 | 只想知道有没有可计算孔，却调用整套对齐分组；分组每添一个元素复制数组 | 使用短路查找；在本次函数内部原地追加分组数组，不修改输入 |
| 导出 | 打开图表或更改显示选择就生成逐孔、板内汇总及字典 | 完整导出计算移到导出操作中，普通渲染不生成这些产物 |
| 失败反馈 | PNG 渲染错误会成为未处理 Promise；部分退出路径不释放临时 URL | 单一图表组件中捕获浏览器导出失败、提示用户，并在 finally 释放 URL |
| 依赖/样板 | 无调用的登录模块、D1 数据库、Drizzle 配置和示例 notes API | 删除 6 个样板文件及两项直接依赖；删除无数据库产品的迁移复制逻辑。Git 可恢复 |
| 打包/验证 | 每次构建删除整个历史离线目录；测试任取首个目录 | 内容哈希区分同日版本，保留旧包；`latest.json` 指向本次产物；校验 ZIP 和全新解压 HTML 的 SHA256 |

## 应当保留的保护

- Imported Baseline、Draft Snapshot、Applied Snapshot：三者是不同业务事实，且未修改时共享数组，并不是无意义复制。删除它们会破坏撤销、复原及结果一致性。
- 缺失、未检出、无效值、真正的 0：不能一律转成 0 或 Ct=40。
- 布局覆盖、越界、跨板身份及未完成的人工复核：这些检查保护实验解释，不应为了少写条件而跳过。
- 单孔 n<2 时 SD/SEM 为空，技术复孔不能当作生物学重复。
- 用户提供 ΔCq/ΔΔCq 时不重建物理板，不自动再次归一化；上游内参标注仅作溯源。
- 审计、原始测量只读与同板内参配对：仍由现有领域边界保证。

## 当前架构与责任

```text
文件 → 解析/映射/人工纠错 → CanonicalDataset
                              ↓
                 不可变 AnalysisSession
                [导入基线 | 草稿 | 已应用]
                     ↓ 命令       ↓ 按依赖投影
                  修改/审计     QC、科学结果
                                  ↓
                      概览 / 板工作区 / 结果
                                  ↓ 用户导出
                        表格 / 共用图表组件
```

职责定位：`session.ts` 处理业务状态迁移；`projection.ts` 处理派生视图；`qpcr-core` 处理科学计算及审计函数；React 处理选择、表单、导航与展示。无需为每种操作创建 service/helper/adapter 类。

## 性能证据

命令：`npm run benchmark`。同机 Node 环境，纯合成 TSV，384 孔/板，批改 384 个孔；3 次预热、15 次测量。旧版由 `git archive 6444d54` 解出，使用同一基准脚本和依赖。以下是中位数；脚本也输出 P95。

| 场景 | 原版 ms | 重构版 ms |
| --- | ---: | ---: |
| 1 板：命令迁移 | 5.801 | 0.424 |
| 1 板：编辑＋视图计算 | 6.630 | 1.293 |
| 10 板：命令迁移 | 54.623 | 0.333 |
| 10 板：编辑＋视图计算 | 87.507 | 9.302 |

10 板完整测量路径约快 9.4 倍（耗时减少约 89%）。这里只度量同步状态/计算，不含 DOM 绘制、文件解析、PNG/XLSX 编码，也不是对全部负载的性能承诺。旧 UI 已有 React useMemo，因此重复投影的微基准不能解释成“以前每次选孔都重算”。

## 尚未解决的风险与后续优先级

1. **P1：合并来源的逐字段溯源。** `canonicalize.ts` 合并多个文件时，仅保留一个优先行 `rawRow`；该行可能来自修正布局，而 Cq 来自仪器文件。原始数据仍在 `dataset.sources`，但逐孔导出的单个 source_file/raw_row 字段不能充分表达混合来源。应做明确的来源模型/导出版本升级，不能靠再添一个随意的 fallback 假装解决。本次保留兼容性，没有改写历史字段含义。
2. **P1：依赖安全债务。** 本次 `npm audit --omit=dev` 报告 5 项（1 critical、3 high、1 moderate），主要涉及 Next 及传递依赖。扫描结果不等于实际部署已可利用：本产品没有使用相关服务器图片/鉴权/数据库功能，且以 vinext 运行；仍需单独验证版本兼容并修补。没有执行 `audit fix --force`，没有把审计扫描当作渗透测试。
3. **P2：入口组件仍过大。** `QpcrAnalysisStudio.tsx` 仍混有导入流程、板编辑操作与视图选择。后续应按完整交互职责拆出 ImportController 和 PlateWorkspace，而不是把每个条件移动成一个小 helper。该改动需继续覆盖选择、跨板、取消及导入替换全流程。
4. **P2：大文件解析仍在主线程。** 本次移除了已证实的重复计算，但 XLSX 库仍进入初始 bundle，生产构建保留 >500kB chunk 提示。若真实大文件造成长任务，应先量测解析/编码，再决定 worker 或延迟加载；必须同时保住离线 `file://` 路径，不能重复引入旧的空白页问题。
5. **P2：科学策略与质量提示仍需独立审阅。** 导出中的基础算术已统一，但参考中心、跨板权重、效率校正及校准样本误差的解释仍是领域策略，不能仅靠减少代码行数合并。图上的提示仍混有假设/溯源/质量提醒，应进一步分类；暂不能把每个圆点都解释为异常复孔。
6. **P2：CSS/双语文案仍有历史混杂。** 修复了观察到的导入操作溢出，没有声称完成全站视觉重设计；剩余重复覆盖应结合具体页面/视口逐步清理。
